# Source audit — 31 October 2026

Reviewed the maintained extension, webview assets, planning and generation workflows, language helpers,
theme generator and packaging scripts. The checkout contains substantial unpublished coding-assistance
and source-structure work; the audit fixes are committed separately from those existing changes.
This is a source and automated-test review, not a claim that every runtime path is defect-free.

## Confirmed issues fixed in 0.0.23 alpha

| Area | Problem | Correction and evidence |
|---|---|---|
| Chat lifecycle | A cancelled reply could reappear after New Chat; two sends could overlap while storage was pending. | Reserve the reply before waiting for storage; discard callbacks from prior conversations. Regression covers cancellation, late completion and concurrent sends. |
| Agent routing | An asynchronous project-stage lookup could replace the agent selected by a planning skill. | Resolve the active skill again before applying the project-stage result. |
| Chat reading | The full render always scrolled to the bottom, even when reading older messages. | Preserve the scroll position for background refreshes; follow new conversation messages explicitly. Webview regression exercises both paths. |
| File generation | Manual scaffolding could overwrite a file created while its picker was open; file existence checks also raced with other writers. | Use exclusive file creation and recheck the plan after selection. Regression creates a competing file between the check and write. |
| Tree persistence | Updating statuses replaced an object-shaped tree with a plain array and could overwrite unrelated statuses from an older snapshot. | Preserve the original wrapper and merge only changed statuses. Scaffolding runs through the serialized write queue. |
| Saved references | Leading `#` markers passed validation but lost map/impact associations; malformed optional fields could crash consumers. Duplicate architecture anchors silently overwrote one another. | Normalize read references and optional fields, reject duplicate anchors, and recognize requirement IDs beyond three digits. |
| Edit freshness | Editing a source file during generation left selection offsets referring to old text. | Fingerprint the full source and reject a stale response before proposing an edit. Regression also covers changes beyond the context excerpt. |
| Model failures | Streamed API errors and output limits could look like successful partial replies; CLI failures were ignored after any text arrived. | Propagate these failures so the caller cannot turn the response into a file proposal. Mock endpoint and actual fixture-process tests cover the failures. |
| Theme maintenance | Running the theme generator reverted previously corrected foreground colors, including the Paper Settings heading. | Match the generator to shipped themes. Regression verifies exact generated output and 4.5:1 contrast for key text/background pairs in Paper and Night. |

## Remaining validation and limits

- Reinstall and inspect the actual editor in Paper and Night, narrow and wide layouts, Settings, keyboard
  shortcuts, chat choices, maps and generated-file review. No installed application was changed in this audit.
- Live authenticated provider calls and a complete VSCodium rebuild were not run. Provider failure tests
  use local fixtures. The full build script resets its disposable VSCodium checkout, so it was inspected without executing it.
- Planning validation establishes document structure and reference validity. It does not prove every
  requirement has sufficient design detail or test coverage; that still needs review of the particular project.
- Brain analysis remains bounded to 5,000 mapped code files and 1,500 AI summaries per run. Large-project
  completeness and long-running sessions still need representative live use.
- The existing unpublished features remain separate working-tree changes and are not included in this audit commit.
